# DZ1 — отчёт по заказам клиентов

Консольное приложение на .NET 10 для формирования агрегированного отчёта по заказам клиентов. Приложение читает данные из CSV-файла, рассчитывает общую стоимость заказов и определяет наиболее часто покупаемый товар.

## Возможности

- принимает один или несколько `client_id` типа `long`;
- поддерживает ввод идентификаторов через пробелы и табуляции;
- рассчитывает сумму всех позиций клиента с учётом количества товара;
- определяет любимый товар по суммарному количеству купленных единиц;
- выводит отчёт в консоль или сохраняет его в новый текстовый файл;
- выбрасывает специализированное `ClientNotFoundException`, если клиент отсутствует в данных;
- использует трёхслойную архитектуру и dependency injection;
- содержит модульные тесты на NUnit.

## Требования

- .NET SDK 10.0 или новее;
- кодировка входного CSV-файла — UTF-8.

Реализации зависимостей регистрируются в `Presentation/Program.cs` через `Microsoft.Extensions.DependencyInjection`. Классы приложения создаются контейнером DI, а не напрямую через `new`.

## Формат входных данных

Файл `orders_log.csv` содержит заголовок и строки со следующими столбцами:

| client_id | order_id | item_name | item_quantity | item_price |
| --- | --- | --- | ---: | ---: |
| 1010 | 1 | Огурчики маринованные | 1 | 100 |
| 1010 | 1 | Чипсеки | 4 | 99.99 |
| 1020 | 2 | Сырок со сгущенкой | 20 | 33 |

Рабочий файл находится в `Infrastructure/orders_log.csv`. Во время сборки он копируется в каталог вывода приложения, откуда его читает `ReportDAO`.

Каждая строка должна содержать:

- `client_id` — идентификатор клиента (`long`);
- `order_id` — идентификатор заказа (`long`);
- `item_name` — название товара (`string`);
- `item_quantity` — количество товара (`int`);
- `item_price` — цена одной единицы товара (`decimal`, разделитель дробной части — точка).

## Сборка и запуск

Восстановить зависимости и собрать решение:

```bash
dotnet restore DZ1.slnx
dotnet build DZ1.slnx
```

Первый аргумент запуска задаёт режим вывода: `console` или `file`.

### Вывод в консоль

```bash
dotnet run --project Presentation/Presentation.csproj -- console
```

После запуска введите один или несколько идентификаторов:

```text
Введите id клиентов через пробел:
1010 1020
```

Каждый отчёт выводится отдельной строкой в формате:

```text
client_id<TAB>orders_sum<TAB>favorite_item_name
```

Пример:

```text
1010    5412.15    Чипсеки
1020    9809.56    Сыр
```

Сумма форматируется с двумя знаками после запятой. Если несколько товаров имеют одинаковое максимальное количество, выбирается любой из них.

### Сохранение в файл

```bash
dotnet run --project Presentation/Presentation.csproj -- file
```

После ввода идентификаторов новый файл создаётся в каталоге вывода приложения. Имя имеет вид:

```text
report_dd-MM-yyyy_HH-mm-ss-fff.txt
```

При запуске из Visual Studio файл обычно появляется в `Presentation/bin/Debug/net10.0`. Повторный запуск в режиме `file` создаёт новый файл, не перезаписывая предыдущий отчёт.

## Обработка ошибок

Если введённое значение не является корректным `long`, приложение попросит повторить ввод.

Если в `orders_log.csv` нет записей для запрошенного клиента, выбрасывается `ClientNotFoundException` с сообщением о том, что клиент не найден в заказах.

Режим запуска обязателен:

```bash
dotnet run --project Presentation/Presentation.csproj
```

В этом случае приложение сообщит о необходимости передать аргумент `<console|file>`.

## Тестирование

Запустить все тесты:

```bash
dotnet test DZ1.slnx
```

Тесты проверяют координацию компонентов `ReportApp`, формирование отчёта сервисом, расчёт суммы и любимого товара в `ReportDAO`, исключение для неизвестного клиента, разбор пользовательского ввода и формат вывода в консоль.

## Архитектура

### Domain

Содержит модели предметной области `Order` и `Report`.

### Application

Содержит бизнес-сценарий формирования отчёта и абстракции:

- `ReportApp` координирует чтение идентификаторов, создание отчётов и их запись;
- `ReportService` формирует `Report` через `IReportDAO`;
- `IReportWriter` абстрагирует способ вывода;
- `IConsoleReader` абстрагирует ввод идентификаторов;
- `ClientNotFoundException` описывает отсутствие клиента в заказах.

### Infrastructure

Содержит реализации работы с данными и файловым выводом: `ReportDAO` читает и агрегирует данные из CSV, а `FileReportWriter` сохраняет результат в новый `.txt`-файл.

### Presentation

Содержит точку входа приложения, `ConsoleReader` и `ConsoleReportWriter`. В `Program.cs` выбирается реализация `IReportWriter` в зависимости от аргумента запуска, после чего зависимости передаются через DI.
